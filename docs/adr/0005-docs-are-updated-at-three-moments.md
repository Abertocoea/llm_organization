# Docs are updated at three moments, not continuously

A project's `docs/` is updated when a qualifying decision is made (an ADR), at the end of a feature (five questions, touching only files where the answer is yes), and at the end of a session (one log entry). Updating on every edit would cost tokens and fill `docs/` with what the code already says; updating only at the end of a project would lose the traps and reasons. The end of a feature is the point where the structure is stable and the memory still fresh.
